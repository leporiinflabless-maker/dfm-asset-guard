# dfm-asset-guard 操作说明手册

> 适用版本：**v1.0.9**（2026-10-10）　仓库：https://gitee.com/mhwpub/dfm-asset-guard ｜ https://github.com/leporiinflabless-maker/dfm-asset-guard

---

## 一、产品组成

| 组件 | 说明 |
|---|---|
| `DFMMonitor/` | 定制监控面板（悬浮窗 + 任务栏窗口）：显示 资产 / 哈夫币 / 状态；内含 DeltaGuard 插件 |
| `DFMMonitor/plugins/DeltaGuard.dll` | 三角洲资产监控插件：面板数据来源、右键菜单命令、设置对话框 |
| `dfm-guard/dfm-guard.exe` | 守卫服务（纯 VC++）：采集、规则判定、邮件告警、自动冻结、登录态保活、重新授权 |
| `dfm-guard/dfm-authcap.dll` | 登录态抓取组件（“重新授权”使用；注入微信网络进程，挂钩 SSL 明文层） |

**零 Python 依赖**：整个产品为纯 VC++，解压即用；不依赖 Python、frida 或任何浏览器。

## 二、安装与启动（解压即用）

1. 将整包解压到任意目录（**不要放在系统 Temp 目录**，否则配置会转存到 `%APPDATA%`）。
2. 配置守卫（首次使用必做）：
   - 把 `dfm-guard/service_config.example.json` 复制为 `service_config.json`（与 dfm-guard.exe 同目录）；
   - 填写：`email.server_token`（服务器代发令牌）、`email.to`（接收告警的邮箱）。
3. 双击 `DFMMonitor/DFMMonitor.exe`。插件会**自动查找并拉起** `dfm-guard.exe`（相对路径，无需手动启动）。
4. 悬浮窗出现并显示实时数据（资产 / 哈夫币 / 监控状态）。

> 首次启动窗口自动放置，拖动到合适位置即可（位置自动记忆）。

## 三、DFMMonitor 使用

### 悬浮窗 / 任务栏窗口
- 悬浮窗宽度随内容自动调整；任务栏窗口同步显示数据。
- 状态含义：
  - `监控中`：服务正常；
  - `已暂停`：监控被暂停（菜单可恢复）；
  - `服务离线`：守卫未运行（插件会自动拉起，稍候即可；仍未恢复见“常见问题”）；
  - `已冻结`：账号处于冻结状态。

### 右键菜单（悬浮窗/任务栏窗口均可）
- 通用：置顶 / 鼠标穿透 / 锁定窗口位置 / 显示任务栏窗口 / 显示主窗口 / 窗口不透明度 / 其他功能 / 选项 / 退出；
- **「三角洲资产监控」子菜单**：
  | 命令 | 说明 |
  |---|---|
  | 暂停/继续监控 | 暂停后不再采集与触发 |
  | 立即刷新 | 立即执行一次采集 |
  | 手动冻结 三角洲行动 | 真实冻结（有确认提示） |
  | 解冻 三角洲行动 | 解除冻结（有确认提示） |
  | 刷新账号列表 | 重新拉取绑定账号 |
  | 发送测试邮件 | 用当前邮件设置发一封测试信 |
  | 打开数据目录 / 打开配置(记事本) | 便于排查 |
  | **重新授权（抓取微信登录态）** | 会话失效后恢复（见第六节） |

### 检查更新
- 启动时自动检查（可在 设置-常规 关闭），或右键菜单 →「检查更新」；
- 更新源为本项目 Gitee 仓库，发现新版本可一键前往下载页。

### 走马灯提示
- 每 30 分钟在悬浮窗与任务栏窗口播放 3 遍提示（单击窗口打开 https://mhw.pub）。

## 四、DeltaGuard 设置（面板右键 → 三角洲资产监控 → 插件选项）

| 分组 | 项目 | 说明 |
|---|---|---|
| 采集 | 采集频率 | **3-600 秒**；默认 30 秒 |
| 条件组合 | 任一满足 / 同时满足 | 多条规则的组合方式 |
| 动作模式 | 邮件通知 / 全自动冻结 / 邮件+全自动 | 触发后的动作 |
| 冻结账号 | 账号下拉 | 选择要冻结的三角洲账号（含微信账号） |
| 触发控制 | 连续命中 / 冷却 | 连续 N 次命中才触发；触发后冷却期不重复动作 |
| 资产规则 | 启用 / 比较符 / 阈值 | 输入框右侧**实时显示 M/K 单位**（如 5M、2.64M）；**上限 300M** |
| 哈夫币规则 | 同上 | |
| 邮件设置 | 模式 | **服务器代发**（推荐）/ 本机 SMTP；SMTP 模式需填授权码 |
| | 服务器代发 | 代发地址（默认 https://mhw.pub）+ 代发令牌 |
| | 收件人 / 测试邮件 | 分号分隔多个收件人 |

## 五、冻结功能说明

- 触发条件命中后按「动作模式」执行；**自动冻结真实生效**（账号会被踢下线/限制登录）；
- 幂等保护：已冻结时跳过重复冻结；解冻同理；
- 任何动作都会记录到 `data/events.jsonl`，并可按订阅发邮件（见第七节）；
- 手动冻结/解冻：右键菜单；解冻后规则若仍满足，会在冷却结束后再次触发（请注意）。

## 六、Cookie / 登录态提醒（未读取到时）

采集数据需要读取「**三角洲行动**」微信小程序的 Cookie（保存在采集器配置中）。
当程序**未能读取到该 Cookie**（小程序登录态失效 / Cookie 缺失 / 离线刷新失败）时：

- **悬浮窗与任务栏窗口会以走马灯方式滚动提醒**：
  「未读取到三角洲小程序Cookie，请在微信打开「三角洲行动」小程序」；
- 提醒期间约每 90 秒重播一次（每次 3 遍滚动），**恢复后自动停止**、回到正常数据显示。

**恢复方法**：
1. 在微信里打开一次「**三角洲行动**」小程序（停留几秒，让本地登录态刷新）；
2. 无需其他操作：服务在下次采集时会自动重新读取 Cookie 并恢复；若仍失败会继续走马灯提醒。

> 说明：采集鉴权失败时，服务会**先自动尝试**从微信本地存储离线刷新 Cookie（纯 C++）；
> 只有自动刷新也失败时才会进入上述提醒状态。
> 触发原因可查看 `data/events.jsonl` 与 `runtime/state.ini` 的 `last_error` / `cookie_ok` 字段。
>
> 数据目录定位：程序会**自动定位**微信数据目录（`%APPDATA%\Tencent\xwechat\radium`，**与微信安装路径无关**，
> 一般无需任何配置），并自动兼容旧版布局与扫描兜底；如需手动指定可设置环境变量 `DFM_RADIUM_ROOT`。

### 腾讯游戏安全中心登录态

执行冻结/解冻需要「**腾讯游戏安全中心**」的登录态（保存在 `cookies.json`，由守卫每 2 分钟持续刷新保活）。
未获取到该登录态时：

- 悬浮窗与任务栏同样以**走马灯**提醒：
  「未获取到腾讯游戏安全中心登录态，请在面板右键「重新授权」」；
- **恢复方法**：右键任一窗口 → 三角洲资产监控 → **重新授权（抓取微信登录态）**，
  并按第七节的步骤在微信打开一次「腾讯游戏安全中心」页面，即可自动恢复；
- 多条提醒（小程序 Cookie / 安全中心登录态）会**交替显示**，全部恢复后自动停止。

## 七、「重新授权」（重点）

### 何时需要
- 收到「**游戏安全中心登录态已失效**」告警邮件；
- 或冻结动作失败，事件显示 `AuthExpired`；
- 或长时间（跨天）未使用后登录态被服务器注销。

### 操作步骤
1. 面板右键 → 三角洲资产监控 → **重新授权（抓取微信登录态）**（命令行等价：`dfm-guard.exe reauth`）；
2. 确认后，**在微信里打开一次「腾讯游戏安全中心」页面**：微信顶部搜索 `腾讯游戏安全中心` → 打开 → 点进「冻结查询」停留几秒；
3. 抓取完成后自动写入 `cookies.json` 并恢复登录态（提示“✅ 已捕获新登录态”）。

### 原理与状态
- 守卫把 `dfm-authcap.dll` 注入微信网络进程，在 SSL 明文层捕获流量并解码（HTTP/2 + HPACK），
  提取 `openid / eas_sid / access_token` 写入 `cookies.json` —— **全程纯 C++**；
- 进度可查看：`runtime/state.ini` 的 `auth_capture=`（waiting/ok/fail）与 `data/authcap.log`。
- 抓取组件注入后**持续驻留**（不自动卸载），同一微信会话内可**多次重新授权**。

## 八、邮件通知

- **服务器代发（推荐）**：守卫将告警 POST 到 `https://mhw.pub/api/guard/notify`（令牌鉴权），由服务器 SMTP 统一发出；
  无需在每台机器上配置邮箱授权码；
- **本机 SMTP**：直接使用本机配置的邮箱（如 QQ 授权码）发送；
- 事件订阅（`email.on`）：`trigger`（触发）/ `freeze` / `unfreeze` / `collect_error` / `auth_error`；
- 登录态失效告警每 1 小时最多一封，避免打扰。

## 九、微信版本依赖说明（重要）

「重新授权」的抓取功能运行在微信的网络进程内，**依赖微信模块 `flue.dll` 的固定函数偏移**：

| 项 | 当前适配值 |
|---|---|
| 微信客户端版本 | **4.1.15**（Windows 版，已验证 4.1.15.13）<br>官方下载：https://dldir1v6.qq.com/weixin/Universal/Windows/WeChatWin_4.1.15.exe |
| 微信 XWeb 运行时 | **RadiumWMPF flue 25715**（随上述客户端版本安装） |
| 挂钩函数 | `SSL_write = flue 基址 + 0x5d42f0`；`SSL_read = flue 基址 + 0x4cbfc00` |
| 模块路径 | `...\xwechat\xplugin\plugins\RadiumWMPF\<版本>\extracted\runtime\flue.dll` |

> **建议使用与适配一致的微信版本（4.1.15）**。若使用其他版本，抓取可能不工作：
> 可安装上述 4.1.15 版本（下载地址见上），或联系维护者适配你的微信版本。

### 依赖的影响面
- **仅影响「重新授权」抓取**。采集、规则、邮件、冻结、登录态保活均**不依赖**微信版本；
- 日常保活（HTTP 接口）与微信客户端版本无关，只要登录态有效即可长期运行。

### 微信升级后可能出现的症状
- 重新授权后提示“已注入”，但一直等待、始终不出现 `CAPTURED`；
- 或注入/挂钩即失败（`data/authcap.log` 无“钩子已安装”）。

### 处理办法
- 联系维护者**重新定位偏移**（更新 `dfm-authcap.dll` 中的两个偏移值并重新编译）即可，其余流程不变；
- 定位方法（维护者参考）：用 frida 挂钩脚本 `ssl_hook.js` 在新版微信中重新扫描 `SSL_write/SSL_read`
  地址（对照 `flue.dll` 基址换算出新偏移），验证后更新组件；亦可对 `flue.dll` 做特征扫描（函数序言）自动定位。

### 查看当前微信运行时版本
- 打开目录 `%APPDATA%\Tencent\xwechat\xplugin\plugins\RadiumWMPF\`，其中**数字最大的文件夹名即当前版本**；
- 或任务管理器 → 微信网络进程 → 模块 → `flue.dll` 路径中的版本号。

## 十、常见问题

| 现象 | 处理 |
|---|---|
| 面板显示“服务离线” | 等待插件自动拉起（约 10 秒）；仍离线则手动运行 `dfm-guard\dfm-guard.exe run` |
| 收不到邮件 | 检查 `service_config.json` 的 `email.to` / `server_token`；用「发送测试邮件」验证 |
| 检查更新失败 | 网络问题，稍后重试；更新源为 Gitee，确保可访问 |
| 采集失败自动降频 | 连续失败会自动退避（最多 5 分钟一次），恢复后自动正常 |
| 悬浮窗不显示 | 是否在系统 Temp 目录运行？是否被“全屏时隐藏”设置隐藏？右键任务栏图标检查 |
| 重新授权一直等待 | 确认已**在微信里打开页面**；仍无效则参照第九节（微信版本依赖） |
| 悬浮窗/任务栏跑马灯提示“未读取到三角洲小程序Cookie” | 打开微信一次「三角洲行动」小程序即可自动恢复（见第六节） |
